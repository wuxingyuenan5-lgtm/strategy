# 均线有效跌破统计 v0.2 — 设计规格

日期：2026-08-16
基线：v0.1.3
开发分支：`agent/ma-breakdown-v0.2`

## 1. 目标

V0.2 不是对旧 HTML 的手工改版，而是把“指数历史数据 → 均线计算 → 候选跌破 → 真跌破周期 → 事件指标 → 条件风险/持续时间/跨指数统计 → HTML 渲染”固化成可重复执行的完整分析流程。第一版整体视觉框架与八个页面保持不变，只更新研究定义、样本、统计内容和必要的展示细节。

## 2. 方案选择

### 采用方案：完整可复现研究流水线

在 v0.2 分支新增数据获取、标准化、事件识别、统计、验证和 HTML renderer。报告中的数字必须全部由当前数据与当前代码生成。

### 不采用方案 A：只修改 HTML

优点是快；缺点是数字不可追溯、无法证明新定义已真正重算，后续每次修改继续依赖人工拼接，因此拒绝。

### 不采用方案 B：一次性 Notebook/脚本，不固化数据合同

可以完成本轮重算，但后续无法稳定复用，也不利于版本比较，因此拒绝。

## 3. 指数与样本

正式研究指数调整为 7 个：

1. 上证指数
2. 上证50（新增）
3. 沪深300
4. 中证1000
5. 创业板指
6. 科创50
7. 中证红利

删除中证全指。

样本起点：

- 上证指数、上证50、沪深300、中证1000、中证红利：统计事件统一从 `2005-01-04` 开始；若正式指数历史可用起点晚于该日，则从官方/供应商可验证的实际可用起点开始，并在报告注明。
- 创业板指、科创50：按各自正式可用历史起点，不强行补前史。
- 原始数据必须额外读取足够的 warm-up 区间用于 MA20/MA25 计算；warm-up 数据不作为事件样本。
- 数据终点沿用当前研究冻结日 `2026-07-31`，本版先与 v0.1.3 维持同一终点，便于版本间纯口径比较。

## 4. 价格口径

研究信号、Peak、Trough、甲乙丙及修复价格全部统一使用日线 `Close`，不混用 High/Low。

## 5. 真跌破、假跌破与完整周期

### 5.1 候选跌破

- Day1：前一交易日 `Close >= MA`，当日 `Close < MA`。
- Day2：Day1 后连续第 2 个交易日 `Close < MA`。
- Day3：Day1 后连续第 3 个交易日 `Close < MA`。

### 5.2 真跌破

只有 Day1、Day2、Day3 连续三日收盘均在对应均线下方，才定义为一次“真跌破”。

Day1 或 Day2 后在形成 Day3 前重新出现 `Close >= MA`，本次候选视为假跌破；假跌破不进入主事件库、甲乙丙、跌幅深度或持续时间统计。

### 5.3 真收回

真跌破形成后，第一次出现连续 3 个交易日收盘均在对应均线上方，定义为“真收回”。

- R1：这组三日真收回中的第 1 日。
- R2：第 2 日。
- R3：第 3 日，确认真收回。

中间只有 1–2 日站上均线而未完成连续三日，则为假收回，事件周期不结束。

### 5.4 完整事件

主历史分布仅使用已经完成 R3 真收回的完整事件。

截至样本终点仍未完成 R3 的真跌破事件，单列为“进行中事件”，不进入甲乙丙和完整历史分布，以避免右截尾造成的 Trough 与持续时间偏差。

一轮真收回完成后，后续新的真跌破按新事件处理，不再事后合并。

## 6. Peak 与 Trough

### Peak

对每个完整事件，以 Day1 前 10 个交易日（不含 Day1）为搜索窗口：

`Peak = max(Close[D1-10 : D1-1])`

若最高 Close 多次出现，Peak 日期取距离 Day1 最近的一次。

### Trough

`Trough = min(Close[D1 : R3])`

若最低 Close 多次出现，Trough 日期取第一次出现，用于唯一确定“多久见底”。

## 7. 甲、乙、丙

### 甲1

`Trough / Close_D1 - 1`

表示首次跌破后，到本轮最终最低点的最大剩余下跌。

### 甲2

`Trough / Close_D2 - 1`

表示连续两日跌破后，到本轮最终最低点的最大剩余下跌。

### 甲3

`Trough / Close_D3 - 1`

表示真跌破确认后，到本轮最终最低点的最大剩余下跌。V0.1.3 的原“乙”在 V0.2 中归入甲3。

### 乙

`Trough / Peak - 1`

表示以 Day1 前 10 个交易日最高收盘为近期高点，本轮完整均线跌破周期的最大回撤幅度。

### 丙

仅对最终完成 R3 真收回的事件计算：

`Close_R1 / Close_D1 - 1`

R1 是最终被 R3 验证为真收回的那组三日中的第一天，不使用中途失败的假收回 R1。

## 8. 真假跌破成功率

单独建立候选信号统计，不污染主事件库：

- Day1 候选最终形成 Day3 真跌破的成功率 / 假跌破率。
- 已经到 Day2 后最终形成 Day3 的条件成功率 / 失败率。

Day3 本身为真跌破定义，不再计算“成功率”。

## 9. 跌幅深度分析

V0.2 不再以均值为中心，甲1/甲2/甲3/乙统一重点展示：

- Median
- P75
- P90
- P95
- Mean（辅助）
- Extreme
- 跌幅超过 3%、5%、10%、15%、20% 的事件概率

同时比较 MA20 / MA25 与各指数，关注等待 Day1→Day2→Day3 对尾部风险的真实减少幅度。

## 10. 持续时间分析

核心时间指标：

1. `D1 → Trough`：首次跌破后多久见底
2. `D3 → Trough`：真跌破确认后多久见底
3. `Trough → R1`：见底后多久第一次进入最终成功的收回序列
4. `Trough → R3`：见底后多久完成真收回
5. `D1 → R3`：完整均线跌破周期
6. `D1 → P1`：第一次重新达到或超过 Day1 Close 的交易日；P1 搜索不在 R3 停止，可跨越该事件周期继续向后寻找

P1 截至样本终点仍未出现时标记为右截尾/未收复，不强行参与普通均值。

展示：Median、P75、P90、Mean、Max，并使用交易日区间 `<=3 / 4-5 / 6-10 / 11-20 / 21-40 / 41-60 / >60`；P1 额外增加 `61-120 / >120 / 未收复`。

增加累计完成概率：

- 已见底比例（Trough）
- 已完成真收回比例（R3）
- 已收复 Day1 价格比例（P1）

固定窗口以 D1 为主锚点，统计 3/5/10/20/40/60 交易日：

- 截至该日收益
- 该窗口内最大跌幅

另做 D1 vs D3 的简洁确认成本/剩余风险时间对比。

## 11. 条件风险分析

V0.2 初版由数据探索筛选真正有区分度的条件，不预设所有变量都进入最终报告。候选字段至少包括：

- D3 相对 MA 偏离度
- D1→D3 跌幅
- Peak→D1 回撤
- Peak→D3 回撤
- MA20/MA25 斜率
- Price 相对 MA60/MA120/MA200
- 前 20/60 日收益
- ATR% / 20 日实现波动率及其历史分位
- 同期其他研究指数处于真跌破状态的比例/数量

筛选原则：优先保留对甲3/乙尾部风险或见底时间表现出稳定单调性、明显分层差异且具有交易解释力的变量。

主展示采用“条件分组 → 中位跌幅 / P90跌幅 / >5%概率 / >10%概率 / 中位见底时间”，相关系数只作辅助。

## 12. 时段与信号图表

保持原页面定位，但升级为当前事件定义：

- 年度/市场阶段真跌破数量
- MA20 vs MA25 真跌破频率
- Day1/Day2 候选的真跌破成功率时间变化
- 典型事件价格路径图标记 Peak、D1、D2、D3、Trough、R1、R3、P1
- 必要时用归一化事件路径展示不同风险档位的平均/中位演化

不展示与新定义不一致的旧“首次单日收回即结束”图表。

## 13. 跨指数传导

使用共同可观测样本，并按新真跌破定义重算：

- 指数 A 真跌破后 5/10/20 个交易日内指数 B 出现真跌破的条件概率
- 同日或滚动窗口真跌破共振数量
- 大盘（上证50/沪深300）与小盘/成长（中证1000/创业板/科创50）的方向传导
- 中证红利作为防守风格对照

所有传导率必须使用 A/B 同时有有效数据的共同样本作分母，避免旧版分母错误。

## 14. 事件明细

事件主表至少保存：

- index / MA
- Peak date / Peak close
- D1/D2/D3 date + close + 当日 MA
- Trough date / close
- R1/R2/R3 date + close
- P1 date / close / 是否右截尾
- 甲1/甲2/甲3/乙/丙
- D3 偏离 MA
- Peak→D1 / Peak→D3
- 各持续时间字段
- 条件风险分组所需状态字段
- 同期跨指数共振度

HTML 事件明细保留筛选与排序能力；不再在桌面端对普通表格强制显示无意义横向滚轴。

## 15. HTML 与视觉约束

- 沿用 v0.1.3 的整体页面框架、卡片风格、顶部导航、八个页面和交互范式。
- 顶部导航桌面端不显示横向滚动条；宽度不足时允许压缩间距或换行。
- 研究设计页必须把 V0.2 全部核心定义明确写出，不能只放公式不解释边界条件。
- 大型宽表允许在真正超宽时做响应式处理，但普通表格不制造无意义 scrollbar。
- HTML 中所有统计数字均来自生成 payload，不在模板中手填研究结论数字。

至少验证：

- MA20/25 rolling 与手工窗口一致
- 典型路径中真跌破/假跌破/假收回/真收回状态机
